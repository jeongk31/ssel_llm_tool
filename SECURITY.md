# Security policy

## Supported version

Security fixes are applied to the current `main` branch and the production service.
Older commits and generated packages are not maintained as separate supported versions.

## Reporting a vulnerability

Please report suspected vulnerabilities privately to
[jkl499@nyu.edu](mailto:jkl499@nyu.edu). Include the affected component, reproduction
steps, potential impact, and any suggested mitigation. Do not include participant data,
API keys, credentials, or other sensitive material in the report.

Please do not open a public GitHub issue for an unremediated vulnerability. Receipt will
be acknowledged as soon as practicable, after which the maintainers will investigate,
coordinate a fix, and determine when public disclosure is appropriate.

API keys and participant datasets should never be committed to this repository. If a
credential is exposed, revoke it with the relevant provider before contacting the
maintainers.
